### Walkthrough presented

- **Names.** `BlobHash` is the full 32-byte blake3 digest. A blob's path is derived from that hash, and the file holds exactly the stored bytes.
- **Opening.** `BlobStore::open` requires the run directory to already exist and be durable. It refuses a missing one; creating the run directory is the caller's job.
- **Writing.** `put` writes a temporary file, flushes it, renames it into place atomically, then flushes the directory.
- **Duplicates.** A `put` of content that already exists verifies the existing file and flushes it, rather than trusting the name.
- **Reading.** `get` rehashes the bytes and returns them only if they still match their name. Errors are `Missing`, `Corrupt` or `Io`.
- **Repair.** A `put` over a corrupt blob replaces it atomically with the correct bytes.
- **Scope.** No runtime code calls the store yet.
- **Not measured.** The cost of fsync, reads and hashing.
- **Results.** 9 blob tests and 95 workspace tests pass. 57 real-binary regression checks pass. The formal admission model is unchanged and does not model the file system. Hosted CI (including the 1.89 MSRV job) is green.
